PHP2Shell vérification de serveurs
CVE-2026-109618 · CVE-2026-109619

Vérifiez si votre serveur est vulnérable à PHP2Shell

Deux RCE critiques dans le cœur de PHP — CVE-2026-109618 et CVE-2026-109619. Corrigées le 21 octobre 2026 dans les versions 8.5.12, 8.4.27, 8.3.36 et 8.2.35. La vérification est passive : une requête vers le site et uniquement les en-têtes publics.

Vérification du serveur

Le schéma est facultatif — nous ajoutons https://. Seuls http et https sont pris en charge.

Adresse issue d'un lien. Confirmez que le serveur est le vôtre, puis cliquez sur « Vérifier le serveur ».

Jusqu’à 10 requêtes séquentielles, uniquement sur une liste blanche : /phpinfo.php, /info.php, /test.php, /php.php, /?phpinfo=1, /status?full, /ping et 3 easter eggs PHP. Uniquement pour les serveurs dont vous êtes propriétaire.

Ce que montre la vérification

Version de PHP

Les en-têtes Server et X-Powered-By, si le serveur les expose.

Deux CVE

Statut pour chacune : vulnérable, probablement vulnérable, non vulnérable ou inconnu.

Que faire

Versions cibles de mise à jour et mesures temporaires qui réduisent le risque.

La vulnérabilité n'est pas exploitée : aucune requête vers d'autres ports ou chemins.

Comment nous vérifions

  • De façon passive : une ou deux requêtes GET/HEAD ordinaires vers la racine du site.
  • Sans exploitation : la vulnérabilité n'est pas déclenchée, l'état du serveur ne change pas.
  • Uniquement des données publiques : en-têtes Server, X-Powered-By, Set-Cookie et marqueurs PHP dans le corps.
  • Sans balayage : aucun port, chemin, dictionnaire ni fuzzing.

Ce que signifie le verdict

Le contrôle n'utilise que ce que le serveur divulgue publiquement : le verdict est une estimation du risque, pas une preuve d'exploitation.

Vulnérable
La version de PHP divulguée est inférieure à la version corrigée pour les deux CVE ou pour l’une d’elles.
Probablement vulnérable
La version appartient à une branche affectée, mais le niveau de correctif exact ne peut pas être confirmé.
Non vulnérable
La version divulguée est égale ou supérieure à la version corrigée — aucune mise à jour n’est nécessaire.
PHP non détecté
Aucun signe de PHP n’a été trouvé — ces CVE ne concernent pas le serveur.
Inconnu
La version de PHP n’a pas pu être déterminée : un audit manuel est nécessaire.

Questions fréquentes

Le contrôle modifie-t-il quelque chose sur le serveur ?

Non. Il s’agit d’une requête passive : nous lisons les en-têtes publics et n’exécutons jamais de code vulnérable.

Puis-je vérifier un serveur qui ne m’appartient pas ?

Uniquement avec l'accord du propriétaire. Le formulaire exige de confirmer que le serveur vous appartient ou que vous êtes autorisé à le vérifier.

Quelle est la précision du résultat ?

Le verdict repose sur la version de PHP divulguée. Les distributions rétroportent souvent des correctifs, des faux positifs sont donc possibles : vérifiez les cas douteux manuellement.

Que faire si le serveur est vulnérable ?

Mettez à jour PHP vers 8.5.12, 8.4.27, 8.3.36 ou 8.2.35 selon votre branche. Si la mise à jour est impossible, appliquez les mesures temporaires du rapport.

Que sont CVE-2026-109618 et CVE-2026-109619 ?

Deux failles RCE critiques dans le cœur de PHP, toutes deux notées 9.2 : l’une suit une erreur de mémoire insuffisante, l’autre vient d’un état obsolète du worker PHP-FPM entre deux requêtes.

Quelles versions de PHP sont corrigées ?

Les versions corrigées sont 8.5.12, 8.4.27, 8.3.36 et 8.2.35. Les branches 8.1, 8.0, 7.x et 5.x n’ont reçu aucun correctif : toutes leurs versions sont vulnérables.

Qu’envoie exactement le contrôle ?

Une ou deux requêtes GET ou HEAD ordinaires vers la racine du site. Le contrôle ne lit que les en-têtes publics et ne touche ni aux autres ports ni aux autres chemins.

Le service est-il gratuit ?

Oui. Le contrôle est gratuit, sans inscription, et le code source est ouvert sur GitHub.

Conservez-vous les adresses que je vérifie ?

Non. Il n’y a ni base de données ni historique. Le journal de l’API ne note que la méthode et le chemin HTTP, et le résultat revient dans votre navigateur sans être enregistré.

Et si le site masque sa version de PHP ?

Le verdict est alors unknown : l’exposition ne peut pas être déterminée à distance. Vérifiez la version sur le serveur lui-même ou mettez PHP à jour vers une version corrigée.
