How we check

  • Passively: one or two ordinary GET/HEAD requests to the site root.
  • No exploitation: the vulnerability is not triggered and the server state does not change.
  • Public data only: Server, X-Powered-By and Set-Cookie headers and PHP markers in the body.
  • No scanning: no ports, paths, wordlists or fuzzing.

What the verdict means

The check uses only what the server discloses publicly, so the verdict is a risk estimate, not proof of exploitation.

Affected
The disclosed PHP version is below the fixed release for both CVEs or for one of them.
Likely affected
The version belongs to an affected branch, but the exact patch level cannot be confirmed.
Not affected
The disclosed version is at or above the fixed release — no update is needed.
PHP not detected
No PHP signs were found — these CVEs do not apply to the server.
Unknown
The PHP version could not be determined: a manual audit is needed.

Frequently asked questions

Does the check change anything on the server?

No. It is a passive request: we read public headers and never run vulnerable code.

Can I check a server that I do not own?

Only with the owner's permission. The form requires you to confirm that the server is yours or that you are allowed to check it.

How accurate is the result?

The verdict is based on the disclosed PHP version. Distributions often backport patches, so false positives are possible: verify doubtful cases manually.

What should I do if the server is vulnerable?

Update PHP to 8.5.12, 8.4.27, 8.3.36 or 8.2.35 for your branch. If you cannot update, apply the temporary mitigations from the report.

What are CVE-2026-109618 and CVE-2026-109619?

They are two critical RCE flaws in the PHP core, both rated 9.2: one follows an out-of-memory error, the other comes from stale PHP-FPM worker state between requests.

Which PHP versions are fixed?

The fixed releases are 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Branches 8.1, 8.0, 7.x and 5.x received no official release, but distributions and Sury publish backports: check the package version.

What exactly does the check send?

One or two ordinary GET or HEAD requests to the site root. The check reads public headers only and never touches other ports or paths.

Is the service free?

Yes. The check is free, needs no account, and the source code is open on GitHub.

Do you store the addresses I check?

No. There is no database and no check history. The API log records only the HTTP method and path, and the result goes back to your browser without being saved.

What if the site hides its PHP version?

The verdict is then unknown: exposure cannot be determined remotely. Check the version on the server itself or update PHP to a fixed release.
